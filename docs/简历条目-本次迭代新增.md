## 二、分组 bullet（按能力维度，可挑 3–5 条用）

### A. 产品定义与「可核验」设计（本轮核心）

- 针对「AI 生成物无法溯源」的信任缺口，设计**资产档案卡（Asset Passport）**：点击任意 3D 模型或
  左侧条目，即显示该资产的 Lux3D 任务号、原始 prompt、文件体积、是否为当前版本。把生成过程从
  「黑箱结果」变成可当场核对的生产记录。
- 设计**生成台账抽屉**，以单表列出全部 **10 条 Lux3D 任务号**（覆盖 character / creature / prop /
  scene 四类实体），点任一行即定位到场景中对应模型。使「技术栈是核心支撑」这一评审项从文字宣称
  变为**评审可自行点开的证据**，而非贴在 PPT 上的标签。
- 复用单一事实来源：台账数据由 `scripts/asset_tasks.json` **派生**为 `web/assets/asset-ledger.json`，
  一并带出 taskid、prompt、类型与真实字节数，避免「文档一份、页面一份」长期漂移。

### B. 性能与可用性工程（本轮含 3 个自查发现的缺陷）

- 重构首屏加载策略：新增 `planSlots()` 按目标尺寸预算站位、`frameAll()` 支持槽位占位对象、
  生成流程拆为「首个实体就绪即出画面 + 其余并发补齐」。精灵森林首屏加载量由 **91.6 MB 降至
  21.2 MB（-77%）**，且镜头一次框住全部槽位，后续模型填入不跳帧。
- 定位并修复**取景裁切**缺陷：槽位按预测尺寸计算、真实模型更宽，导致最右侧实体被切出画面；
  改为全部实体就绪后按真实包围盒二次收镜，并引入 `userInteracted` 状态，用户拖动视角后
  不再自动改镜头，避免与用户抢夺相机控制权。
- 定位并修复**占位体尺寸失配**缺陷：占位几何体为写死尺寸（场景占位 footprint 4.6 vs 槽位预算 3.6），
  写作新实体时会冲出取景框；改为按包围盒归一化至 `TARGET_SIZE` 并以缩放后包围盒回填尺寸元数据。
- 优化线上交付体积：发布前剔除 221 MB 历史模型备份目录，站点由 **447 MB 降至 226 MB（-49%）**；
  发布后以 HTTP 实测复核构建标记（`planSlots`、`userInteracted`、`asset-ledger.json` 均通过），
  而非依赖平台"发布成功"提示。

### C. 技术写作与材料交付

- 独立撰写 **13 页项目报告书**，新增「Lux3D 生成台账」专页（10 行任务号表 + 3 个指标 + 口径脚注），
  并将全书页码由 `/12` 统一改版为 `/13`；同步将旧 12 页草稿归档，消除误交旧版的风险。
- 全套材料口径自查：README / 交付计划 / 简历素材 / 提交清单四处的页数与特性描述在一次迭代内
  全部对齐，无残留旧数字。
- 输出传播素材体系 v2：5 张 1080×810 配图（含台账抽屉这一差异化截图）+ 3 个标题备选 + 420 字正文
  + 话题组合；并就用旧笔记还是重发作判断——依据是旧笔记 1 赞 0 评论、内容对应旧界面、无保护价值。

### D. 交付与验收习惯（可迁移的方法论）

- 对提交材料做**反向核验**：把平台上已提交的报告书下载回本地解包，确认页数 13、第 9 页含台账与
  任务号，而不是相信表单页显示的文件名。
- 逐条实测对外链接（Demo 首页 / 构建标记 / 台账 JSON / 源码仓库 / 社交笔记跳转），发现并修正
  标题误带序号、话题漏项两处瑕疵。
- 三次缺陷均为「以第一个用户身份完整走一遍主流程」时发现，而非等待外部反馈。
