## 一、项目定位（一句话）

**让"写作即造物"的 Web 应用**：创作者在散文里用轻量标记 `[[名称:类型:描述]]` 内联描述 3D 实体，系统解析后逐个调用 **Aholo Lux3D 文生 3D** 生成资产，并拼装成可旋转、可点击聚焦的交互式 3D 场景，一键在线分享。

选题名：**StoryLight3D**（已备好报名简介 `docs/pitch.md`）。

---

## 二、技术架构

```
┌─ 用户输入：故事散文（含 [[name:type:desc]] 标记）
│
├─ 前端解析  story-parse.js
│     正则提取 → 实体列表（去重）
│
├─ 资产生成  Lux3D 通道（API key 已验证可用 ✅）
│     授权载体：Aholo API key（经用户连上的 aholo-lux3d MCP 连接验证——
│               余额 3600、可提交文生3D任务；MCP 即 key 的授权通道，规避 key 文本复制难题）
│     生成方式 A（本项目采用）：经 MCP 调 post_createtextto3dtask → gettask → 下载 GLB
│     生成方式 B（用户自部署用）：scripts/generate_assets.mjs --key <key> 直连 REST API
│     产出：GLB 模型文件
│
├─ 场景拼装  Three.js
│     加载 GLB → 按实体坐标/焦点排列 → 缩略图导航
│
├─ 交互预览  轨道旋转 + 点击聚焦 + 加载进度
│
└─ 在线分享  发布为静态站点（WorkBuddy 站点 / GitHub Pages）
```

**三档资产加载策略**（已内置）：
1. `manifest` 优先：预生成的真实 GLB（生产用）
2. 实时调用：网页内直连 Lux3D（需处理 CORS/密钥暴露，谨慎）
3. 占位兜底：无 key/无网时用基础几何体，保证流程可演示
