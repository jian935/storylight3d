01

问题不在于没有 3D 工具

而在于入口放错了位置：用户不是想学建模，是想让故事被看见。

卡点

想造物的人，先被迫成为 3D 从业者

写作者脑子里有画面，但要把它变成 3D，得先过建模、UV、材质、灯光、渲染。现有 AI 3D 工具还要求"上传图 / 进另一个界面写 prompt"，创作被迫离开叙事现场。

洞察

3D 的价值不在模型，在"叙事被看见"

所以产品形态不该是"3D 编辑器 + 生成按钮"，而应是写作界面 + 一层极轻的标记。像 Markdown 之于排版：多写几个符号，换结构化能力，不必打开排版软件。

03

三个关键取舍

产品判断体现在"放弃什么"，不是"加了什么"。

取舍 01

内联 DSL，不做表单编辑器

表格化会退化成 3D 工具、打断写作流。代价：要学 1 条语法，复杂空间关系表达不了。

取舍 02

预生成优先 + 三档兜底

现场演示不能等每个资产约 5 分钟。预生成 GLB → 实时生成 → 占位几何体，永不白屏。代价：新增实体要重跑脚本。

取舍 03

纯前端零后端

部署成本≈0、故事不上传服务器、打开即用。代价：无持久化、无协作、刷新即丢。

05

边界与诚实说明

  • 资产观感受 G1-Turbo 与 prompt 限制；早期纯材质描述偏暗，已改用带色相词的 prompt 重生成。
  • 字幕为近似逐词对齐（edge-tts 无 WordBoundary 时间轴）。
  • DSL 表达力有限：无层级、无相对位置、无动画、无材质参数。
  • 无账号 / 无持久化 / 无多人协作；移动端为单列布局。
06

面试问答（6 问）

按真实情况准备，不编数据。

Q1 怎么发现需求

我是写作者，也是 3D 门外汉

卡点不是"没有 3D 工具"，而是工具要求我先变成 3D 从业者。于是把"3D 应该能内联进写作"做成一个可运行的假设。

Q2 为什么用 DSL

可视化编辑器会打断写作流

三段式刚好够驱动生成、又短到能写进散文。代价是表达力有限——第一版要验证的是入口，不是精度。

Q3 怎么定义"做好了"

三层可观测指标

实体解析召回、资产加载成功率、首次可交互时间。没做用户测试，所以不报留存/满意度。

Q4 失败过一次

资产在暗场景里大片发黑

PBR 金属/水晶缺环境贴图，叠加 G1-Turbo 对纯材质描述不上色。自建 PMREM 环境 + 重写带色相词的 prompt 重生成。

Q5 成本与延迟

约 5 分钟/资产，用产品设计绕开

预生成 + 三档回退：演示走预生成（快、稳、不暴露密钥），新增实体才触发实时生成。

Q6 边界在哪

复杂空间 / 动画 / 协作不做

第一版要证明"写作可以成为 3D 的入口"；入口不成立，做动画没意义。优先级比堆功能重要。
